### 第 1 轮前置分析

**1. 可以先出草图原型，确认后再开发。**
完全支持“线框/交互草图原型 -> 确认骨架 -> 更新规范 -> 编码落地”的两阶段流程。我们可以先产出一个可直接在浏览器中点击切换、零后端改动成本的低/中保真 HTML 交互原型，等你拍板整体骨架、信息层级和操作路径后，再重构 `web/src`。

**2. AI 全栈体系下有哪些可执行的 UI 规范与标准（以及 OpenUI 的定位边界）**
结合本项目已在 [design-plan.md](file:///home/luwei/workspace/github/ai-web-free/openspec/specs/ui/design-plan.md) 中落地的架构，业界通常按**四层分层标准**来执行，各自职责不同：

1. **生成式交互协议层（OpenUI / A2UI / AG-UI / MCP-UI）**
   - 本项目已接入的 Thesys **OpenUI（`@openuidev/react-lang` + `@openuidev/react-ui`）** 与 **A2UI**、**AG-UI** 同属 **Agent-to-UI 流式协议标准**：核心价值是**用 Schema（`zod`）约束大模型在对话流里安全地流式输出图表、表格、表单卡片**。
   - **关键边界**：OpenUI **不负责**整站后台的导航骨架、侧边栏布局、网关运维表格交互与视觉设计系统；此前骨架显得不专业，很大程度上是直接沿用了纯手写 CSS（[styles.css](file:///home/luwei/workspace/github/ai-web-free/web/src/styles.css)），且把对话式入口当成了全局主骨架。
2. **设计系统与组件规范层（Design Tokens + `shadcn/ui` / Radix UI + Tailwind CSS）**
   - 这是目前 AI 全栈控制台与 SaaS 产品的事实工业标准：通过 **Design Tokens（语义化 CSS 变量：层级背景色、边框对比度、间距步进 `4px/8px`、字号/字重梯度）** + **Radix UI / `shadcn/ui` 组件原语规范** 统一弹窗、表格、筛选、表单校验、键盘焦点与无障碍细节，视觉
