## 1. 背景与问题定义 (Context & Problem Statement)

- **原始 `/grill-me` 诉求**：解决 GitHub Secrets (`VPS_ENV_CONTENT`) 无法查看完整明文、每次改动单一业务配置都需要全量粘贴覆盖并触发重新发布的痛点；明确 `.env` 兼容边界、数据库持久化、多环境 `global + profile` 继承、敏感字段加密回显、动态热刷新以及人性化系统配置 UI（`#/settings`）。

## 2. 决策树访谈记录 (Decision Drivers & Grill-Me Q&A)

#### 决策分支 1（单选）：`.env` 与数据库系统配置中心的职责边界与覆盖优先级

> **已选决策**：分层职责 + 数据库优先（Bootstrap 极简引导层如 `DATABASE_URL`、`SERVER_PORT`、`APP_PROFILE`、`ADMIN_TOKEN` 保留在 `.env`；其余业务/代理/云端 Key/热池策略全部迁移进数据库配置中心。优先级：`DB Profile 覆盖值 > DB Global 全局值 > .env 环境变量 > 代码默认值`，首次启动自动种子导入 `.env` 非空业务项，之后以数据库为准）。

#### 决策分支 2（单选）：多运行环境（`home` / `office` / `vps`）下的作用域设计

> **已选决策**：支持 `global` 全局 + `profile` 环境级两层继承（通用业务配置默认全局共享；环境相关配置支持在特定 Profile 下设置覆盖值，一键恢复继承全局）。

#### 决策分支 3（单选）：敏感配置项（API Key、订阅链接、Secret）加密存储与明文回显

> **已选决策**：AES-GCM 加密落库 + 列表掩码回显 + 按需点击「查看/编辑明文」调用 Reveal 接口解密回显，彻底解决 GitHub Secrets 无法看明文的痛点。

#### 决策分支 4（单选）：修改系统配置后的运行时热生效（Hot-Reload）范围

> **已选决策**：全链路动态热刷新（保存后原位更新 `*config.Config` 及进程环境视图，按变更域触发 `provider.ApplyConfig`、号池 `SetPolicy` + `Rebalance` 与代理池同步，全程零停机生效）。

#### 决策分支 5（单选）：前端管理台入口与组织方式

> **已选决策**：独立一级菜单 `#/settings`（「系统配置中心」），采用左侧分组导航 + 高频核心快速上手页签 + `.env` 批量导入/导出 + 敏感明文即点即改 + 底部浮动保存栏。

#### 决策分支 6（单选）：CI/CD `deploy.yml` 与 VPS `.env` 的协同升级

> **已选决策**：`deploy.yml` 升级为智能按键合并保留模式，保留服务器已有 `.env` 中未被 `VPS_ENV_CONTENT` 覆盖的键，使 `VPS_ENV_CONTENT` 只需固化极简的 4~5 行引导配置。

## 3. 落地方案与影响范围 (Implementation Plan & Consequences)

详细架构规范见 [`openspec/specs/gateway/system-config-center.md`](../../openspec/specs/gateway/system-config-center.md)，核心落地包括：
1. `internal/db/models.go` & `internal/db/settings.go`：`SystemSettingRecord` 数据模型（接入 SQLite ↔ Neon PG 物化双向同步）与 AES-GCM 加密读写。
2. `internal/config/settings_catalog.go` & `internal/bootstrap/bootstrap.go`：全量配置项目录元数据、启动自动 `.env` 种子迁移与四级优先级热合并。
3. `internal/handler/settings_handler.go` & `internal/handler/router.go`：`/admin/api/v1/settings*` 增删改查、明文 Reveal、`.env`/JSON 导出及全链路热刷新钩子。
4. `web/src/views/SettingsView.tsx`：深度人机工程设计的 `#/settings` 系统配置中心页面。
5. `.github/workflows/deploy.yml`：智能合并 `.env` 部署流程。
