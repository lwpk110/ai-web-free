#### 决策分支 1（单选）：针对「免费TTS、免费视频生成（Muse）与短剧工作流」这组点子，你希望在项目中如何定位整体的产品与架构形态？

#### 决策分支 2（单选）：关于「免费 TTS」的架构落地，网关标准 /v1/audio/speech 接口与音色调度应采取哪种技术选型？

候选方案：
- (Recommended) 多引擎路由（内置 Edge-TTS 免凭据短剧主力音色 + 保持兼容 ChatGPT 逆向音色 + 预留克隆源）：通过标准 /v1/audio/speech 自动按 voice/model 调度，内置微软晓晓/云希/云扬等短剧解说与戏剧音色，零额外鉴权即可使用
- 专注 Edge-TTS 深度定制：针对短剧台词强化情感表现力，全面支持 SSML 标签、语速、音高调节与多角色对话合成，彻底免除账号额度消耗
- 可插拔通用适配器（支持开源克隆如 CosyVoice/Fish-Audio/GPT-SoVITS）：网关只定义规范，允许管理员在后台配置外部开源 TTS 服务的 URL 与音色映射表
- 双轨并行：内嵌轻量纯 Go/WSS Edge-TTS 作为内置基座，同时在控制台支持为不同短剧角色上传参考音频（即调用克隆服务）

> **已选决策**：(Recommended) 多引擎路由（内置 Edge-TTS 免凭据短剧主力音色 + 保持兼容 ChatGPT 逆向音色 + 预留克隆源）：通过标准 /v1/audio/speech 自动按 voice/model 调度，内置微软晓晓/云希/云扬等短剧解说与戏剧音色，零额外鉴权即可使用

#### 决策分支 3（单选）：关于「免费视频生成（Muse）」，在短剧制作链路中，你希望其重点承担的定位与技术接入方案是什么？

候选方案：
- (Recommended) 双模视频引擎：以 MuseTalk 驱动人物口型对白（角色立绘 + TTS 音频 -> 真实说话视频）为主干，辅以通用图生视频（生成环境运镜与动态动作镜头），网关统一封装为异步标准 /v1/videos 协议
- 专注 MuseTalk 数字人对白生成：短剧的核心资产是人物台词交互，优先打通「角色图 + 配音 -> 口型同步视频」，降低算力与长视频生成的失真风险
- 开放式通用视频网关（/v1/videos 协议）：抽象标准任务接口（POST 提交、GET 轮询），插件支持接入 MuseTalk 本地/云端实例以及主流免费/逆向文生图生视频渠道
- 纯端侧与轻量模板方案：使用 MuseTalk 预设模板，前端直接拼装关键帧动效，后端仅提供轻量转发调度

> **已选决策**：部署muse talk 是 muse from meta

#### 决策分支 4（单选）：鉴于 ai-web-free 遵循零 CGO 纯 Go 架构，关于 Muse / MuseTalk 视频生成服务的部署与网关集成，你希望采用哪种架构方案？

候选方案：
- (Recommended) 独立 GPU 推理微服务 + 网关标准调度（MUSE_API_URL 适配器）：Muse/MuseTalk 独立运行于 GPU 容器或云主机（暴露轻量 FastAPI/Worker），ai-web-free 作为主网关统一管理异步任务队列（提交角色图+音频 -> 状态轮询 -> 视频直链），并提供开箱即用的 docker-compose 联调模板
- 双模兼容（私有部署 + 云端算力托管）：网关视频 Provider 既支持私有部署的 MuseTalk 实例 URL，也兼容 Replicate/HuggingFace 等免自建算力的 Serverless API 接入
- 前端直连推理端点：网关仅下发配置，前端短剧工坊直接与部署好的 MuseTalk API 通信获取渲染视频，减轻 Go 网关的高带宽视频流压力
- 纯协议与排队网关优先：Go 网关只负责标准 /v1/videos 协议、任务持久化与回调通知，视频渲染服务作为纯 Worker 异步消费任务队列

> **已选决策**：不使用硬件，完全以云上 api 调用 为主

#### 决策分支 5（单选）：针对「完全以云上 API 为主、不使用本地硬件」的定位，视频生成（Muse 等）在云端供应商接入与账号号池机制上应如何设计？

候选方案：
- (Recommended) 混合云端号池模式（内置免密/公开云端通道 + 支持多平台免费额度 API 聚合）：既支持接入类似 HuggingFace Space / Meta AI / Web 逆向等免算力云端通道，也支持配置如 SiliconFlow(硅基流动)、Fal.ai、Replicate 等新用户赠送免费额度的 API Key，由号池统一管理配额与轮换
- 纯 Web 逆向免密号池模式：延续 ai-web-free 的账号池特性（类似 ChatGPT Web 逆向），针对有免费额度的云上视频平台（如 Meta AI 网页版、剪映、可灵 Web）维护 Cookie/Token 自动化生成与轮换
- 标准三方 Serverless API 转发池：仅接入具备规范 REST API 的云端服务商，网关实现负载均衡、重试与失败转移，不维护高风险易失效的私有 Web 逆向逆向协议
- 由用户在前端配置云端临时 Token / Webhook：网关只定义调度骨架，调用云端三方接口的凭据与回调由用户在控制台自行填报与管理

> **已选决策**：(Recommended) 混合云端号池模式（内置免密/公开云端通道 + 支持多平台免费额度 API 聚合）：既支持接入类似 HuggingFace Space / Meta AI / Web 逆向等免算力云端通道，也支持配置如 SiliconFlow(硅基流动)、Fal.ai、Replicate 等新用户赠送免费额度的 API Key，由号池统一管理配额与轮换

#### 决策分支 6（单选）：在前端「短剧创作工坊」的交互形态与流转模式上，你更倾向哪种设计方案？

候选方案：
- (Recommended) 分步向导式流水线（剧本大纲 -> 角色立绘与音色绑定 -> 分镜拆解 -> 批量音视频渲染 -> 播放器时间轴），支持导出剪映/CapCut草稿与打包 ZIP
- 一键全自动管线（输入小说/剧本梗概，一键全自动生成全套分镜视频），中途支持对个别失败分镜单独重试或修改台词与画面
- 对话引导式交互（基于现有的 Generative Workbench + OpenUI 交互式卡片）：通过 AI 助手逐步提问与引导，动态在对话流中渲染角色卡片、分镜表与试听播放器
- 自由看板式（Kanban / Storyboard Board）：以分镜卡片墙的形式自由拖拽排序、批量上传素材、绑定台词并触发云端渲染

> **已选决策**：(Recommended) 分步向导式流水线（剧本大纲 -> 角色立绘与音色绑定 -> 分镜拆解 -> 批量音视频渲染 -> 播放器时间轴），支持导出剪映/CapCut草稿与打包 ZIP

#### 决策分支 7（单选）：针对短剧工程草稿（剧本、角色库、分镜列表）以及生成的音视频素材，其数据存储与持久化方案应如何设计以符合零 CGO 约束？

候选方案：
- (Recommended) 浏览器 IndexedDB 本地持久化 + 前端零依赖打包（兼具数据隐私与零 CGO 服务端架构）：剧本草稿、角色资产、分镜数据与生成的多媒体 Blob 全程保存在浏览器 IndexedDB，纯静态 Go 网关保持无状态轻量化，一键打包 ZIP / 剪映草稿直接在前端完成
- 双层轻量持久化（前端 IndexedDB 即时自动存盘 + 服务端可选 JSON 目录归档）：日常编辑前端实时存盘防丢失，支持同步/备份至网关 DRAMA_DATA_DIR 目录（纯 JSON 文件存储，符合零 CGO 要求）
- 纯服务端临时会话驱动：由网关分配短剧会话 ID，中间产物（音频/视频）暂存于服务端临时缓存，并在规定时长（如 24 小时）后通过 GC 自动清理

> **已选决策**：双层轻量持久化（前端 IndexedDB 即时自动存盘 + 服务端可选 JSON 目录归档）：日常编辑前端实时存盘防丢失，支持同步/备份至网关 DRAMA_DATA_DIR 目录（纯 JSON 文件存储，符合零 CGO 要求）

#### 决策分支 8（单选）：在短剧分镜自动化生成过程中，如何保障不同分镜镜头之间「角色形象与视觉风格的一致性」？

候选方案：
- (Recommended) 混合三层保障（统一风格预设 + 角色外貌圣经自动注入 + 口型阶段锚定定妆立绘）：项目级锁定视觉风格（如国风3D、电影质感），角色定妆生成特征描述词与正脸立绘，后续所有分镜自动注入角色特征，且 Muse 对口型强制使用定妆立绘保证不崩脸
- 纯提示词外貌注入（角色特征锚定）：在角色定义环节固化发型、面容、服饰标签，分镜生成时通过 LLM 模板引擎自动拼装进生图 Prompt
- 基准图生图链（Image-to-Image / ControlNet 参考）：以首张定妆图作为图生图源图或参考图传递给云端生图/生视频 API，强制风格对齐
- 轻量模板预设：内置多套短剧常见爆款模板（霸总、修仙、末日、穿越），由系统预设好角色 Prompt 与配音方案，用户只需修改台词剧本

> **已选决策**：(Recommended) 混合三层保障（统一风格预设 + 角色外貌圣经自动注入 + 口型阶段锚定定妆立绘）：项目级锁定视觉风格（如国风3D、电影质感），角色定妆生成特征描述词与正脸立绘，后续所有分镜自动注入角色特征，且 Muse 对口型强制使用定妆立绘保证不崩脸

#### 决策分支 9（单选）：关于该功能的具体实施路径与迭代顺序，你希望采取哪种落地策略？

候选方案：
- (Recommended) 渐进式三阶段落地：①网关内置 Edge-TTS 免费音色与试听 -> ②云端视频 Provider 接入与 /v1/videos 协议抽象 -> ③前端短剧工坊五步流水线与剪映草稿导出
- 音视频协议先行：先一次性完成后端 TTS 与云端视频生成网关所有接口规范，再集中开发前端短剧工坊页面
- 短剧工坊原型先行：优先在前端开发短剧工作流向导与时间轴原型（先用现有模型与模拟数据跑通），随后逐步替换为真实的云端 TTS 与视频 API
- 垂直切片单镜头闭环：先做一个最小单镜头闭环（单句台词+单张角色图生成对口型视频并导出），再扩展为完整的多镜头短剧大纲流水线

> **已选决策**：(Recommended) 渐进式三阶段落地：①网关内置 Edge-TTS 免费音色与试听 -> ②云端视频 Provider 接入与 /v1/videos 协议抽象 -> ③前端短剧工坊五步流水线与剪映草稿导出

## 4. 落地方案与影响范围 (Implementation Plan & Consequences)

# 短剧创作工坊与音视频网关（Short Drama Studio & A/V Gateway）设计规范

## 1. 架构定位与工程约束

本规范定义 `ai-web-free` 中「免费 TTS、免费云端视频生成（Muse）与短剧工作流（Short Drama Studio）」的系统架构、网关协议、角色一致性保障体系与前端工坊设计。

- **全栈打通架构**：
  - 后端：扩展 OpenAI 兼容的音频生成（`/v1/audio/speech` 多引擎分流）与视频异步生成（`/v1/videos/generations`、`/v1/videos/:id`）标准接口。
  - 前端：新增可视化「短剧创作工坊（`#/drama`）」，支持五步向导式流水线、时间轴预览播放与一键导出剪映草稿工程。
- **严格零 CGO 与纯静态编译约束（`CGO_ENABLED=0`）**：
  - 生产镜像基于 `gcr.io/distroless/static-debian12:nonroot`，禁止引入任何 CGO 依赖或外部可执行程序假设（无本地 ffmpeg、无本地 python、无本地 C 语言音频编解码器绑定）。
  - TTS 生成与视频任务调度完全由纯 Go 运行时驱动。
- **零本地硬件依赖，100% 云端 API / 免费平台驱动**：
  - 不要求宿主机具备本地 GPU、CUDA 环境或重型本地模型；
  - 视频生成（MuseTalk / Meta AI Muse / 图生视频）完全通过云端免费免密端点（如 HuggingFace Spaces、公开 Web 端点）或赠送额度的云端聚合平台（SiliconFlow、Fal.ai、Replicate）以号池形式调度。
- **双层轻量持久化机制**：
  - 前端 IndexedDB（`ai_web_drama_db`）实时存盘，支撑用户多工程管理、富媒体 Blob 离线缓存与纯前端秒级导出打包；
  - 网关支持配置可选的环境变量 `DRAMA_DATA_DIR`，以纯 JSON 文件原子读写实现项目服务端备份，未配置时保持无状态运行。

## 2. 免费 TTS 多引擎网关设计 (`/v1/audio/speech`)

### 2.1 多引擎路由架构

网关对标准 OpenAI `/v1/audio/speech` 请求提供透明的多引擎调度：

```
客户端请求 POST /v1/audio/speech
           │
           ▼
    【Voice / Model 路由检查】
     ├── voice in [zh-CN-*, 晓晓, 云希, 云扬...] ──► 【Edge-TTS 纯 Go 引擎】(免鉴权、零额度消耗)

```

### 2.2 纯 Go Edge-TTS 引擎规格

- **协议实现**：纯 Go 实现微软 Edge 浏览器大声朗读 WebSocket 协议（`wss://speech.platform.bing.com/consumer/speech/synthesize/readaheadwork/v1`），支持直接流式接收或缓冲为完整音频响应。
- **输出格式**：支持 `mp3`（默认 `audio/mpeg`）、`aac`（`audio/aac`）、`wav`、`opus`。
- **短剧主力音色表**：
  - `zh-CN-XiaoxiaoNeural`（晓晓）：短剧大女主、温柔知性、旁白解说首选。
  - `zh-CN-YunxiNeural`（云希）：沉浸式故事解说、男主对白、情感叙事。
  - `zh-CN-YunyangNeural`（云扬）：专业影视播报、冷酷霸总、男性权威角色。
  - `zh-CN-YunxiaNeural`（云夏）：活泼少女、调皮千金、萌系配角。
  - `zh-CN-YunjianNeural`（云健）：热血少年、修仙反派、武侠剑客。
  - `zh-CN-liaoning-XiaobeiNeural`（辽宁晓北）：特色幽默东北话短剧角色。
  - `zh-HK-HiuGaaiNeural` / `zh-TW-HsiaoChenNeural`：港风剧与台偶剧特色方言音色。
- **参数支持**：
  - `speed`（倍速：`0.5` ~ `2.0`，映射为 SSML `rate` 参数如 `+20%`）。
  - `pitch`（音调：支持 `+10Hz` / `-5st` 微调）。
  - 支持直接在 `input` 中透传 `<speak>` SSML 标签，实现停顿（`<break time="500ms"/>`）与多角色情感强调。

## 3. 云端视频生成网关设计 (`/v1/videos/*`)

### 3.1 接口契约规范 (OpenAI 风格异步视频接口)

#### 提交视频生成任务：`POST /v1/videos/generations`
- **请求体（JSON）**：
  ```json
  {
    "model": "muse-talk",
    "prompt": "极具电影质感的微表情特写，眼神坚定，光线柔和",
    "image_url": "https://.../character_face.png",
    "audio_url": "https://.../speech_line.mp3",
    "aspect_ratio": "9:16",
    "duration": 5
  }
  ```
- **同步返回**：
  ```json
  {
    "id": "vid_20261114_abc123",
    "object": "video.generation",
    "status": "queued",
    "created_at": 1731564000,
    "model": "muse-talk"
  }
  ```

#### 轮询任务状态：`GET /v1/videos/:id`
- **返回结构**：
  ```json
  {
    "id": "vid_20261114_abc123",
    "status": "succeeded",
    "progress": 100,
    "video_url": "https://.../output.mp4",
    "thumbnail_url": "https://.../output_thumb.jpg",
    "duration": 5.2,
    "error": null
  }
  ```
- **状态迁移**：`queued`（排队中） -> `processing`（云端渲染中） -> `succeeded`（完成） / `failed`（失败并返回可读诊断信息）。

### 3.2 云端视频 Provider 号池调度

- **免费云端渠道接入**：
  - **Meta AI / Muse 网页端及云端免密端点**：通过逆向会话池模拟请求，提取生成直链。
  - **HuggingFace Spaces 公开免算力实例**：基于 Gradio Client API 封装，将角色立绘与音频送入公开的 MuseTalk Space 生成口型同步视频。
- **高可用三方 API 聚合**：
  - 支持配置带有免费赠送额度的云端聚合平台（如 SiliconFlow 硅基流动、Fal.ai、Replicate）。
  - 纳入 `ai-web-free` 现有的 `internal/proxy` 代理检测与容灾熔断体系，单渠道超时或限流自动 Failover 切换。
