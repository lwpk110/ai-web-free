## 2. 决策树访谈记录 (Decision Drivers & Grill-Me Q&A)

#### 决策分支 1（单选）：针对字节、阿里及其他平台的免费多模态能力，你希望网关采取哪种整体接入策略与模态优先级？

候选方案：
- (Recommended) 混合双轨制（P0 剪映TTS免登逆向 + 硅基流动永久免费池；P1 字节即梦生图/视频Cookie池 + 阿里云百炼官方Key池）：兼顾零成本逆向爆款（剪映音色、即梦视频）与官方协议高稳定性（硅基、阿里百炼）
- 纯官方 API 免费配额轮询池：仅接入阿里云百炼 DashScope、硅基流动 SiliconFlow、火山方舟等标准 API，通过多 Key 轮询与额度监控，规避逆向协议变动风险
- 纯零成本 Web/客户端逆向号池：聚焦剪映 TTS、即梦 AI 生图/视频、豆包 Web 等完全免额度或每日赠送积分的平台，最大化降低对官方实名账号的依赖
- 音频 TTS 优先专项突破：首期只落地剪映 TTS（200+热门音色）与 CosyVoice 语音合成，图片与视频模态延后至下一阶段迭代

> **已选决策**：(Recommended) 混合双轨制（P0 剪映TTS免登逆向 + 硅基流动永久免费池；P1 字节即梦生图/视频Cookie池 + 阿里云百炼官方Key池）：兼顾零成本逆向爆款（剪映音色、即梦视频）与官方协议高稳定性（硅基、阿里百炼）

#### 决策分支 2（单选）：在多供应商聚合场景下，网关对外暴露的 API 与路由分发机制应如何设计？

候选方案：
- (Recommended) 模型/音色标识精准路由 + 跨渠道降级：按 model（如 wanx-v1、jimeng-4.5、flux-schnell）与 voice 显式路由，当主渠道额度耗尽或熔断时支持同能力跨平台优雅降级（如阿里万相耗尽自动降级为硅基 FLUX）
- 虚拟模型别名抽象层：对外统一暴露虚拟模型（如 free-tts、standard-image、free-video），由网关按当前号池剩余免费配额与健康度动态调度下游最佳供应商
- 严格 Provider 隔离：请求严格按指定的 Provider 派发，仅在同供应商内部的多账号/Key 之间负载均衡，不做跨平台降级调度

> **已选决策**：(Recommended) 模型/音色标识精准路由 + 跨渠道降级：按 model（如 wanx-v1、jimeng-4.5、flux-schnell）与 voice 显式路由，当主渠道额度耗尽或熔断时支持同能力跨平台优雅降级（如阿里万相耗尽自动降级为硅基 FLUX）

#### 决策分支 3（单选）：针对视频生成（即梦 AI、阿里 Wan 视频）等高耗时任务（30s~180s），网关的 API 协议与任务生命周期管理应如何设计？

候选方案：
- (Recommended) 纯 Go 内存任务池 + 异步两阶段与长轮询兼容：POST /v1/videos/generations 创建任务并分配 task_id，任务元信息暂存于零 CGO 内存哈希表（支持 LRU 淘汰与可选 JSON 持久化）；同时支持客户端带 wait=true 参数在超时（如 180s）内自动等待出片直接返回，兼容异步客户端与同步工作流
- 纯两阶段标准异步轮询：严格仅支持 POST 提交获取 task_id 与 GET /v1/videos/tasks/{id} 状态轮询，服务端不维护挂起的长 HTTP 连接，避免并发长请求拖垮网关连接池
- 端侧直连第三方 CDN 直链：网关在即梦/阿里百炼生成完毕后仅负责返回第三方带签名的临时直链（有效期如 24 小时），不反代高带宽的视频二进制流量

> **已选决策**：(Recommended) 纯 Go 内存任务池 + 异步两阶段与长轮询兼容：POST /v1/videos/generations 创建任务并分配 task_id，任务元信息暂存于零 CGO 内存哈希表（支持 LRU 淘汰与可选 JSON 持久化）；同时支持客户端带 wait=true 参数在超时（如 180s）内自动等待出片直接返回，兼容异步客户端与同步工作流

#### 决策分支 4（单选）：针对剪映 TTS 与 CosyVoice 语音合成，在音频长文本处理、流式传输与音色目录暴露上，你倾向哪种实现？

候选方案：
- (Recommended) 智能切片拼接 + 统一音色元数据端点：剪映长文本在网关以标点符号纯 Go 内存切片并发合成并流式拼接输出；新增 GET /v1/audio/voices 端点动态下发剪映 200+ 爆款音色分类（解说/影视/方言）与 CosyVoice 情感音色列表供前端与客户端选择
- 基础原样代理（字数超限直接报错）：不对文本做自动切片，严格限制单次请求文本长度（如 300 字），音色采用静态枚举文档约定，保持网关实现最简
- 流式 Chunked 边下边推：对剪映流式音频接口进行管道反代（Proxy Pipe），不进行内存整包拼接，以极低的首包延迟将音频流推送给下游播放器

> **已选决策**：(Recommended) 智能切片拼接 + 统一音色元数据端点：剪映长文本在网关以标点符号纯 Go 内存切片并发合成并流式拼接输出；新增 GET /v1/audio/voices 端点动态下发剪映 200+ 爆款音色分类（解说/影视/方言）与 CosyVoice 情感音色列表供前端与客户端选择

#### 决策分支 5（单选）：针对即梦每日积分重置、阿里百炼新人额度耗尽、硅基流动速率限制等差异化特征，号池状态机与容灾调度应如何设计？

候选方案：
- (Recommended) 分层状态机与智能按日冷却：即梦检测到积分不足时自动进入「次日重置冷却（冷却至次日 00:05 自动唤醒）」；阿里百炼检测到免费额度耗尽或过期自动标记为「exhausted（已耗尽）」并剔除调度；硅基流动遇到 429 速率限制执行自适应指数退避冷却（30s~120s）；剪映免密通道则绑定独立代理池与请求并发限流器防风控
- 统一简单粗暴冷却策略：任何平台遇到鉴权失败或额度用尽一律按固定时间（如 1 小时）置为休眠冷却，由巡检定时器粗粒度轮询探测重试
- 严格手动维护模式：遇到异常仅在审计日志报警并将状态置为 failure，由管理员在后台控制台手动刷新或替换凭据，不执行自动化自愈

> **已选决策**：(Recommended) 分层状态机与智能按日冷却：即梦检测到积分不足时自动进入「次日重置冷却（冷却至次日 00:05 自动唤醒）」；阿里百炼检测到免费额度耗尽或过期自动标记为「exhausted（已耗尽）」并剔除调度；硅基流动遇到 429 速率限制执行自适应指数退避冷却（30s~120s）；剪映免密通道则绑定独立代理池与请求并发限流器防风控

#### 决策分支 6（单选）：在 Web 控制台（React 管理端）中，你希望如何呈现与体验这套免费多模态 API 体系？

候选方案：
- (Recommended) 全流程运维与工坊联动：在「号池管理」新增 ByteDance / DashScope / SiliconFlow 专属标签页（展示积分状态、失效时间与多Key导入）；在控制台新增「语音试听工坊（TTS Studio）」与「视频工坊」，同时将即梦/万相无缝注入现有「图像工坊」供一键直观体验
- 专注号池管理与参数配置：仅在后台管理端增加多渠道凭据导入与健康检查面板，前端不对 TTS 和视频进行图形化交互制作，多模态能力完全留给第三方客户端（如 Cherry Studio / NextChat / 脚本）调用
- 轻量聚合看板：仅在仪表盘（Dashboard）中增加一个免费多模态状态概览卡片，展示各供应商的连通性与调用次数，不改动其他子页面

> **已选决策**：(Recommended) 全流程运维与工坊联动：在「号池管理」新增 ByteDance / DashScope / SiliconFlow 专属标签页（展示积分状态、失效时间与多Key导入）；在控制台新增「语音试听工坊（TTS Studio）」与「视频工坊」，同时将即梦/万相无缝注入现有「图像工坊」供一键直观体验

# 免费多模态 API 网关与号池系统设计规范 (Free Multi-Modal Providers Specification)

## 1. 目标与设计原则

为 `ai-web-free` 扩展覆盖 **字节跳动（ByteDance）**、**阿里云（Alibaba Cloud）** 与 **硅基流动（SiliconFlow）** 等主流平台的免费多模态服务，在严格遵循 **零 CGO 纯 Go 编译** 与 **OpenAI 兼容协议** 前提下，实现高品质的 **TTS 语音合成**、**AI 文生图/图生图** 与 **AI 视频生成** 网关。

### 核心约束
1. **严格零 CGO**：全量 Go 代码基于纯标准库与纯 Go 依赖（`bogdanfinn/tls-client`、`gorilla/websocket`、标准 HTTP），禁止引入任何 SQLite 或 C 绑定。
2. **混合双轨制**：
   - **轨道一（零成本客户端逆向）**：剪映 TTS（200+ 热门抖音爆款音色，免额度/免登录）、即梦 AI（Cookie 号池，每日 66~88 免费积分生成图片与视频）。
   - **轨道二（官方免费配额池）**：硅基流动（FLUX.1-schnell、CosyVoice 永久免费模型）、阿里云百炼 DashScope（CosyVoice、通义万相、Wan 视频 90 天新人免费额度）。
3. **优雅降级与粘性防风控**：模型与音色显式路由，主渠道耗尽或熔断时跨渠道自动降级，保障下游客户端高可用。

## 2. 接口契约与协议对齐规范

### 2.1 TTS 语音合成接口 (`/v1/audio/speech` & `/v1/audio/voices`)

#### 1. 合成请求端点：`POST /v1/audio/speech`
* **请求体格式**：
  ```json
  {
    "model": "tts-1",
    "input": "这是一段需要合成的高清语音文本，支持超长篇幅自动切片...",
    "voice": "zh_female_shuangkuai",
    "response_format": "mp3",
    "speed": 1.0
  }
  ```
* **音色路由规则**：
  * 若 `voice` 以 `zh_`、`dy_` 开头或属于剪映音色库，调度至 `internal/provider/jianying`。
  * 若 `voice` 属于 `cosyvoice-*` 或指定 `model: "cosyvoice-v1"`，优先调度至硅基流动免费池；若配置了百炼 Key 则可使用百炼定制音色。
  * 若 `voice` 为 OpenAI 预设音色（`alloy`, `echo`, `fable`, `onyx`, `nova`, `shimmer`），自动映射至剪映或 CosyVoice 的最接近中文音质音色。
* **智能标点长文本切片引擎**：
  * 单句长度阈值：250 个字符。
  * 分词算法：按中英文换行与标点符号（`\n`, `。`, `！`, `？`, `!`, `?`, `；`, `;`）切分成有序句子切片。
  * 并发执行：纯 Go 内存协程并发合成分片（带信号量控制防止 429），依序号以流式 Chunked 形式写入 HTTP Response。

#### 2. 音色元数据端点：`GET /v1/audio/voices`
* **响应格式**：
  ```json
  {
    "voices": [
      {
        "id": "zh_female_shuangkuai",
        "name": "双快姐（解说小美）",
        "provider": "jianying",
        "category": "影视解说",
        "gender": "female",
        "sample_text": "注意看，眼前这个男人叫小帅...",
        "tags": ["热门", "解说", "快节奏"]
      },
      {
        "id": "longxiaochun",
        "name": "龙小春（亲切女声）",
        "provider": "dashscope",
        "category": "自然情感",
        "gender": "female",
        "sample_text": "今天的天气真不错，要一起去散步吗？",
        "tags": ["多情感", "大模型拟真"]
      }
    ]
  }
  ```

### 2.2 图像生成聚合接口 (`/v1/images/generations`)

* **请求体格式**：
  ```json
  {
    "model": "wanx-v1",
    "prompt": "赛博朋克未来都市，霓虹雨夜，电影级光影，8k高画质",
    "n": 1,
    "size": "1024x1024",
    "response_format": "url"
  }
  ```
* **供应商派发与降级链**：
  ```mermaid
  flowchart LR
      Req["POST /v1/images/generations"] --> Route{指定 Model}
      Route -->|wanx-v1| W1["阿里云百炼万相"]
      Route -->|jimeng-4.5| J1["字节即梦 AI"]
      Route -->|flux-schnell| S1["硅基流动 FLUX"]

      W1 -.->|配额耗尽/超限| S1
      J1 -.->|当日积分耗尽| S1
      S1 --> Res["返回标准 OpenAI Image 结构"]
  ```
* **异步转同步等待**：
  * 万相与即梦属于异步任务体系，网关内通过 `context.WithTimeout(ctx, 60*time.Second)` 发起短轮询探测，完成后组装标准 OpenAI 响应，避免让轻量级生图客户端适配两阶段复杂协议。

### 2.3 视频生成标准接口 (`/v1/videos/generations` & `/v1/videos/tasks/{id}`)

#### 1. 创建视频生成任务：`POST /v1/videos/generations`
* **请求体**：
  ```json
  {
    "model": "jimeng-video-2.0",
    "prompt": "金色的落叶在秋风中缓缓飘落，镜头平缓向前推进，4k，电影质感",
    "image_url": "https://.../source.png",
    "duration": 5,
    "wait": false
  }
  ```
* **响应格式**：
  ```json
  {
    "task_id": "vtask_jm_01j7b8d4k3",
    "status": "PENDING",
    "created_at": 1731570100,
    "eta_seconds": 60
  }
  ```
  > 若传入 `wait: true`，连接将挂起轮询（最长 180s），完成后直接返回下述任务结果。

#### 2. 轮询视频生成状态：`GET /v1/videos/tasks/{task_id}`
* **响应格式**：
  ```json
  {
    "task_id": "vtask_jm_01j7b8d4k3",
    "model": "jimeng-video-2.0",
    "status": "SUCCEEDED",
    "progress": 100,
    "video_url": "https://lf-dreamina.bytegoofy.com/.../output.mp4",
  ```
