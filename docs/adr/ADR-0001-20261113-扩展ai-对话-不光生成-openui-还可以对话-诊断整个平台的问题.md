### 第 3 轮前置分析

| **Gemini** | **`@` 上下文扩展 + `/` 技能**：在统一对话中按需挂载实时系统数据（Workspace/实时遥测），回答中混排自然语言分析与动态图表/操作卡。 | 当触发平台诊断（如询问熔断、封禁、报错）时，自动挂载号池、代理矩阵、审计日志上下文，无需手动复制报错信息。 |
| **Claude** | **Slash Commands + Artifacts（混合流 / 侧边画布）**：普通推理和排障用自然语言 Markdown 流式输出；遇到结构化 UI 组件或代码时，以独立可交互 **Artifact 卡片**（内联或右侧分栏）渲染。 | 同一条 AI 回复可以**先用 Markdown 讲清楚根因分析与排查逻辑，紧接着内嵌 `openui` 诊断/修复组件卡片**，不再强制整条回复只能写 `root = Card(...)`。 |

> **已选决策**：(Recommended) ChatGPT 式统一流：输入 `/` 选技能胶囊（如 /diagnose、/openui、/fix、/image），消息流内支持「Markdown 分析 + 内联 OpenUI 交互卡片」混排

### 第 5 轮前置分析

接下来确认第 3 个关键分支：**“号池熔断”与“账号封禁”的后端判定逻辑与根因细分**。

在排查现有 Go 代码时，我发现一个关键缺口：
- [account.go](file:///home/luwei/workspace/github/ai-web-free/internal/accounts/account.go#L43) 虽然定义了 `StatusBanned`（已封禁），但**全仓没有任何地方会将账号置为 `StatusBanned`**：
  - [chatgpt_plugin.go](file:///home/luwei/workspace/github/ai-web-free/internal/provider/chatgpt_plugin.go#L362) 在测活遇到 `401/403` 时一律标为 `StatusExpired` 并塞进卡密续期队列；
  - [failover.go](file:///home/luwei/workspace/github/ai-web-free/internal/handler/failover.go#L144) 遇到 `403` 仅当作普通重试，未区分**“账号被 OpenAI 永封（`account_deactivated`）”**还是**“代理 IP 脏触发 Cloudflare/Sentinel 403 盾”**（后者换代理即可恢复，前者继续用 Chrome 续期只会空转浪费资源）。

对于平台诊断的异常归类与状态机升级，你希望覆盖到什么粒度？

#### 决策分支 5（单选）：对于“账号封禁原因”与“号池/代理熔断原因”的底层识别，你倾向于哪种判定策略？

候选方案：
- (Recommended) 升级状态机与根因分类器：精准区分「永封/停用(置为 StatusBanned 并停止空转续期)」「403 风控盾/脏代理 IP」「401 过期(区分有无续期凭据)」「429 全量/生图限流」「代理节点 3 连败熔断」5 大类根因
- 仅在 `/admin/api/v1/diagnostics` 读取现有 `LastError` / `LastRenewError` 文本做正则归类，不修改现有账号状态流转逻辑（不自动置 `StatusBanned`）
- 只要遇到 HTTP 403 或卡密登录失败就一律置为 `StatusBanned`（最严格剔除策略）

> **已选决策**：(Recommended) 升级状态机与根因分类器：精准区分「永封/停用(置为 StatusBanned 并停止空转续期)」「403 风控盾/脏代理 IP」「401 过期(区分有无续期凭据)」「429 全量/生图限流」「代理节点 3 连败熔断」5 大类根因

## 3. 注意事项与避坑指南（Pitfalls）

1. **`web/embed_test.go` 强校验**：
   - `web/embed_test.go` 会检查 `web/system-prompt.txt` 中是否包含 `"PoolOverviewCard"`, `"AccountDiagnosticTable"`, `"ImageStudioCard"`，以及 `web/dist/index.html` 是否包含 `<div id="root"></div>`。
   - 修改 `web/src/lib/openui-library.tsx` 时，**必须同步更新 `web/scripts/export-prompt.mjs`**（因为 `npm run build` 会运行 `node scripts/export-prompt.mjs` 覆盖 `web/system-prompt.txt`），且保留原有 3 个组件名称不变。
2. **禁止污染标准 `/v1/chat/completions` 接口**：
   - 遵循 `AGENTS.md` 约束 #3，后端 `/v1/chat/completions` 仅在携带 `X-OpenUI-Lang: true` 时自动前置注入 `web.OpenUISystemPrompt()`；`#/chat` 的混合模式与诊断上下文通过前端按需组装 `system` 消息实现，普通外部 API 调用完全不受影响。
3. **零 CGO 约束**：
   - 诊断引擎与修复逻辑全部基于现有纯 Go 内存结构（`accounts.Pool`、`proxy.Pool`、`provider.KamiRenewWorker`、`audit.RingBuffer`），严禁引入任何外部 C 绑定依赖。
